# Flexiv Rizon 4 + Sharpa hand (Isaac Sim)

SimToolReal can run with a Flexiv Rizon 4 arm in place of the KUKA iiwa14. The left Sharpa HA4 hand, the 29-joint policy interface (7 arm + 22 hand) and the 140/162-dim observations are unchanged. The pretrained checkpoint is KUKA-specific (its observations contain arm joint coordinates), so a Rizon policy has to be trained.

The real-robot deployment stack (`deployment/`, `isaacgymenvs/utils/observation_action_utils_sharpa.py`) and the legacy Isaac Gym env still assume the KUKA.

## Selecting the robot

Robots are defined in `simtoolreal_shared/robots.py` (`KUKA_IIWA14`, `FLEXIV_RIZON4`). Each spec pins the URDF, arm joint and link names, default and raised arm poses, arm PD gains, base pose and palm-center offset. The Isaac Sim env picks one with `assets.robot`, and the default stays `kuka_iiwa14`:

```bash
.venv_isaacsim/bin/python isaacsimenvs/train.py \
  --task Isaacsimenvs-SimToolReal-Direct-v0 \
  --agent rl_games_cfg_entry_point \
  env.assets.robot=flexiv_rizon4
```

## Robot model

`assets/urdf/rizon4_sharpa_description/rizon4_left_sharpa.urdf` is generated by `scripts/generate_rizon4_sharpa_urdf.py`:

- **Arm:** built from Flexiv's official Rizon 4 parameters and meshes, vendored in `assets/urdf/rizon4_sharpa_description/flexiv_rizon4/` (Apache-2.0; its README records the upstream commit and the one fix to a corrupt face in `link4.obj`). Joints are `rizon4_joint1..7`. Their limits are Flexiv's **soft** limits, because the real controller stops the arm there.
- **Hand:** the `sharpa_mount` subtree of the KUKA URDF, copied verbatim. Its meshes are referenced from `assets/urdf/kuka_sharpa_description/`.
- **Mount:** a fixed `rizon4_flange_to_sharpa_mount` joint, then the hand subtree's `sharpa_mount_joint` with its offset set to the real adapter's 5 mm (`SHARPA_MOUNT_TO_HAND_XYZ`; the KUKA URDF uses 0.05 m). The adapter has no geometry of its own. Fixed joints are merged on import, so `rizon4_link7` is the palm body.

## Derived values

`scripts/compute_rizon4_sharpa_defaults.py` derives these Rizon spec values from the KUKA's:

- **Palm-center offset:** the same physical point on the hand as the KUKA palm center.
- **Default arm pose:** puts the hand at the same world pose as the KUKA default. It is the least twisted inverse-kinematics solution (joints 3 and 5 nearest zero, like the KUKA), at least 10° inside the limits.
- **Raised pose** (`reset.start_arm_higher`, used for DexToolBench eval): the hand at the KUKA's raised pose, using the solution nearest the default.

Add `--reachability` to also compare goal-volume reachability. With the base at the KUKA's position the two arms are close: the palm center reaches 79% (Rizon) vs 80% (KUKA) of the grid in any orientation, and 69% vs 62% at the default hand orientation.

## Placeholders to replace with real measurements

| Value | Where | Current placeholder |
| --- | --- | --- |
| Hand yaw about the flange axis | `FLANGE_TO_SHARPA_MOUNT_RPY` in `scripts/generate_rizon4_sharpa_urdf.py` | the KUKA's −90° (from `sharpa_mount_joint`). The 5 mm adapter offset is measured. |
| Arm PD gains | `FLEXIV_RIZON4.arm_joint_stiffness/damping` | the KUKA gains; fit them by system ID on the real arm |
| Robot base pose relative to the table | `FLEXIV_RIZON4.base_pos/base_quat_xyzw` | the KUKA's `(0, 0.8, 0)` |

After changing the mount, regenerate the URDF, recompute the derived values and paste them into `FLEXIV_RIZON4`, then validate:

```bash
.venv_isaacsim/bin/python scripts/generate_rizon4_sharpa_urdf.py
.venv_isaacsim/bin/python scripts/compute_rizon4_sharpa_defaults.py
OMNI_KIT_ACCEPT_EULA=YES .venv_isaacsim/bin/python isaacsimenvs/tests/test_robot_spec_validation.py --robot flexiv_rizon4
```

The validation test checks four things:
- the palm center the policy observes matches the URDF's forward kinematics;
- the default and raised poses hold without self-collision;
- each arm joint settles after a step;
- random actions stay finite.

Add `--render` to also save PNGs of the default pose (front and side) to `outputs/robot_validation/`, e.g. to check the mount visually.

## Pose viewer

The pose viewer (`isaacsimenvs/tasks/simtoolreal/pose_viewer.py`) loads the robot URDF over HTTP from a GitHub raw base, by default `tylerlum/simtoolreal/main`. That base won't have the Rizon assets until they are pushed, so point `github_raw_base` at a branch that does before using the viewer with `flexiv_rizon4`.
